# CS2021 DID v8 Official-Before Event Report

作成日: 2026-05-20

このレポートは、`cs2021_did_v8 (1)_reg_sensitivity.R` による最新の推定結果を、主分析と感度分析に分けて整理したものである。以前の `official yes/no` は「分析期間のどこかで公式誘導があるか」を見ていたが、今回の版では `official_before_event` を用いて、「同名の非公式 GitHub リポジトリが出現する前に公式誘導が確認されていたか」を区別する。

## 1. 用語説明

### 処置イベント

この分析での処置イベントは、CRAN パッケージに対して、同名の非公式 GitHub リポジトリが後から出現することである。公式 CRAN ミラーや、CRAN パッケージページ・公式リポジトリへの誘導を含むリポジトリは、処置イベントそのものからは除外している。

したがって、この分析で見ているのは「GitHub 上に同名の非公式リポジトリが出現した後、CRAN ダウンロード数がどう変化するか」である。

### treated / never-treated

`treated` は、観測期間中に同名の非公式 GitHub リポジトリが後から出現したパッケージである。今回の DID パネルで使える treated は 3,262 パッケージである。

`never-treated` は、観測期間中に同名の非公式 GitHub リポジトリが出現しなかったパッケージである。比較対象として使える never-treated は 14,802 パッケージである。

### G

`G` は、各パッケージが処置を受けた月を表すコホートである。具体的には、CRAN ダウンロード観測開始から、同名非公式 GitHub リポジトリが出現するまでの月数である。

`G<12` は、CRAN ダウンロード観測開始から12か月未満で処置イベントが起きたパッケージを意味する。この群では、イベント前12か月の十分な情報がないため、`pre12` 仕様には向かない。

### Dynamic ATT

Dynamic ATT は、イベント時点を `e=0` として、イベント後 `e=0..60` か月の平均的な処置効果を集約した推定量である。今回の主な結論を見るための中心的な推定量である。

値は対数ダウンロード数の差として読める。たとえば ATT が 0.35 程度であれば、単純換算では `exp(0.35)-1`、つまり約42%程度の差に相当する。ただし、厳密には DID の条件付き平均差として解釈する。

### Group ATT

Group ATT は、処置時期 `G` ごとの効果をコホート単位で集約した推定量である。処置時期の違いを重視して、「どのコホートでも平均的に正の効果が出ているか」を見るために使う。

### Calendar ATT

Calendar ATT は、暦月ごとの効果を集約した推定量である。時期固有のショックや全体トレンドの影響を意識しながら、全体として処置後の差が残るかを見る。

### Balanced Dynamic

Balanced Dynamic は、イベント後 `e0=12, 24, 36, 48` か月まで観測できるパッケージだけに限定して dynamic ATT を計算するものである。

通常の dynamic ATT では、遠いイベント時点ほど観測できるパッケージが変わる。Balanced Dynamic を併記することで、「長期まで観測できるパッケージだけに限っても、効果が残るか」を確認できる。

### Pre-trend

Pre-trend は、処置前の時点で treated と比較群が同じように動いていたかを確認する診断である。DID の因果解釈では、処置前に大きな差がないことが望ましい。

今回の結果では、多くの仕様で pre-trend が有意であり、とくに `official_before_yes` 群で強い。したがって、推定値が正で頑健である一方、因果効果として断定するには慎重さが必要である。

### official_before_event

`official_before_event` は、同名非公式 GitHub リポジトリが出現する前に、公式誘導が確認されていたかを表す変数である。

ここでいう公式誘導とは、GitHub リポジトリ側に CRAN パッケージページや公式パッケージURLへのリンクがある、または公式リポジトリとして判定されるケースを指す。処置イベントそのものは非公式リポジトリの出現なので、`official_before_event=1` は「イベント前から公式・正規の導線を持っていたパッケージ群」と解釈するのが自然である。

## 2. 分析仕様

### 主分析

主分析では、`G<12` を除外しない。これは、早期にイベントが起きたパッケージも研究対象に含めるためである。

推定式の共変量は以下である。

```text
official_before_event + log_dl_pre3 + pretrend_slope
```

ただし、`official_before_event` で subgroup を作った分析では、その subgroup 内で `official_before_event` は定数になるため、自動的に落とされる。その場合は実質的に以下の式になる。

```text
log_dl_pre3 + pretrend_slope
```

主分析の比較群は `not-yet-treated` である。つまり、ある時点でまだ処置を受けていないパッケージを比較対象に含める。

主分析では次を確認する。

- treated 全体の平均的な処置後変化
- `official_before_event=1` と `official_before_event=0` の subgroup 差
- イベント後 12, 24, 36, 48 か月まで観測できるパッケージに限定した balanced dynamic
- 処置前トレンドの診断

### 感度分析

感度分析では、主分析の結論が仕様変更に対してどれくらい安定しているかを確認する。

今回の主要な感度分析は以下である。

| 仕様 | 目的 |
|---|---|
| `never-treated only` | 比較群を一度も処置されないパッケージだけに限定する |
| `G>=13 pre12` | イベント前12か月を観測できる treated のみに限定し、`log_dl_pre12` を使う |
| `G<12 subgroup` | 早期処置群だけを分けて、結果が特殊でないか確認する |
| `G>=12 subgroup` | 早期処置ではない群だけを分けて、主結果と比較する |
| `official_before_yes + never` | 公式誘導がイベント前にある群で、比較群を never-treated に限定する |
| `official_before_yes + G>=13 pre12` | 公式誘導がイベント前にある群で、pre12 仕様を確認する |
| `official_before_no + never` | 公式誘導がイベント前にない群で、比較群を never-treated に限定する |
| `official_before_no + G>=13 pre12` | 公式誘導がイベント前にない群で、pre12 仕様を確認する |

## 4. 主分析の結果

### 主分析の集計結果

| 仕様 | treated数 | Dynamic ATT | SE | Group ATT | SE | Calendar ATT | SE |
|---|---:|---:|---:|---:|---:|---:|---:|
| 全体 | 3,262 | 0.3569 | 0.0192 | 0.3128 | 0.0174 | 0.2975 | 0.0169 |
| official before yes | 852 | 0.4268 | 0.0458 | 0.3749 | 0.0396 | 0.3721 | 0.0387 |
| official before no | 2,410 | 0.3454 | 0.0206 | 0.3014 | 0.0187 | 0.2851 | 0.0183 |

主分析では、全体の Dynamic ATT は 0.3569 である。これは、同名非公式 GitHub リポジトリの出現後、treated パッケージの CRAN ダウンロード数が比較群に対して相対的に増加していることを示す。

`official_before_yes` 群の Dynamic ATT は 0.4268 で、`official_before_no` 群の 0.3454 より大きい。したがって、イベント前に公式誘導を持っていたパッケージほど、イベント後のDL増加が大きい傾向がある。

ただし、`official_before_yes` は「イベント前から公式の導線がある」群であり、もともとユーザーが到達しやすい、認知度が高い、開発者・利用者コミュニティが活発である、といった特徴を持つ可能性が高い。そのため、これは公式誘導の効果というより、公式誘導を持つようなパッケージの可視性・人気の高さを反映している可能性がある。

### 主分析の Balanced Dynamic

| 仕様 | e12 | e24 | e36 | e48 |
|---|---:|---:|---:|---:|
| 全体 | 0.0682 | 0.1512 | 0.2253 | 0.3016 |
| official before yes | 0.0837 | 0.1892 | 0.2747 | 0.3663 |
| official before no | 0.0615 | 0.1406 | 0.2124 | 0.2879 |

Balanced Dynamic では、全体でも subgroup でも、イベント後の期間が長くなるほど ATT が大きくなる。これは、同名非公式 GitHub リポジトリの出現が、短期的なノイズだけでなく、中長期的なDL差と関連していることを示す。

特に `official_before_yes` 群では、e48 で 0.3663 まで上昇する。これは、公式誘導がイベント前にあるパッケージでは、非公式同名リポジトリ出現後のDL増加が長期的にも大きいことを示している。

### 主分析の Pre-trend

| 仕様 | pre-trendセル | 有意セル | 有意セル割合 | Wald p |
|---|---:|---:|---:|---:|
| 全体 | 7,140 | 879 | 12.3% | 0.0000 |
| official before yes | 6,923 | 1,963 | 28.4% | 0.0000 |

主分析では、全体でも pre-trend は有意である。特に `official_before_yes` 群では有意セル割合が 28.4% と高く、処置前から比較群と異なる動きをしていた可能性が強い。

したがって、主分析の結果は「正の関連が強い」と読むべきであり、「非公式同名リポジトリの出現だけがDL増加を引き起こした」と断定するのは難しい。

## 6. 結果まとめ

第一に、同名非公式 GitHub リポジトリの出現後、CRAN ダウンロード数は比較群に対して相対的に増加している。主分析の Dynamic ATT は 0.3569 であり、`never-treated only` でも 0.3664、`G>=13 pre12` でも 0.3257 である。したがって、主結果は仕様変更に対して一定程度頑健である。

第二に、イベント前に公式誘導があるパッケージでは、推定値が一貫して大きい。主分析 subgroup では `official_before_yes` が 0.4268、`official_before_no` が 0.3454 である。感度分析でも、`official_before_yes + never` が 0.4315、`official_before_no + never` が 0.3553 である。

第三に、`official_before_no` 群でも正の結果が残る。これは、結果が単に「公式誘導のある有名パッケージだけ」で起きているわけではないことを示す。

第四に、Balanced Dynamic では多くの仕様で e12 から e48 にかけて ATT が上昇する。イベント後の差は短期だけではなく、中長期的に広がる傾向がある。

第五に、pre-trend は重要な制約である。とくに `official_before_yes` 群では処置前から比較群と異なる動きをしている可能性が強く、因果効果としての解釈には注意が必要である。

## 7. 考察

今回の結果は、同名非公式 GitHub リポジトリの出現が CRAN パッケージのダウンロード増加と強く関連していることを示している。これは、GitHub 上で同名のリポジトリが作られることが、パッケージの認知、検索可能性、周辺エコシステム上の露出と結びついている可能性を示唆する。

ただし、このイベントを純粋な外生的ショックとして扱うのは難しい。同名非公式リポジトリが作られるパッケージは、そもそも利用者や開発者から注目されている可能性がある。特に `official_before_yes` 群では、イベント前から公式誘導が存在し、pre-trend も強い。これは、処置イベントの前からDLが伸びやすい環境が整っていたことを意味する。

そのため、現時点で最も安全な解釈は次のようになる。

同名非公式 GitHub リポジトリの出現後、CRAN ダウンロード数は一貫して増加する。この関連は複数の感度分析でも残る。ただし、特に公式誘導がイベント前にあるパッケージでは、処置前から成長トレンドが強いため、推定値にはパッケージの可視性・人気・導線の強さが含まれている可能性がある。

論文や発表では、主張の強さを段階的に分けるのがよい。

まず、記述的・実証的事実として「同名非公式 GitHub リポジトリの出現後にDLが増加する」という頑健なパターンを示す。次に、`official_before_event` による subgroup 分析から、「イベント前から公式導線を持つパッケージでは増加幅が大きい」と述べる。最後に、pre-trend の強さを明示し、「これは公式誘導やパッケージ人気を含む可視性の差を反映している可能性があり、純粋な因果効果としては慎重に解釈する」と整理するのが妥当である。

## 8. 次に確認すべき点

今後の改善としては、以下が重要である。

1. `official_before_event` をさらに細分化する。たとえば、公式誘導がイベントの何か月前から存在したかを使うと、単なる yes/no より説得力が増す。
2. イベント前DLトレンドをより柔軟に調整する。`pretrend_slope` だけでなく、事前期間の平均成長率や複数ラグを検討する余地がある。
3. `official_before_yes` 群については、因果推定というより「高可視性パッケージ群の補助分析」として位置づける。
4. 論文本文では、主分析、`never-treated only`、`G>=13 pre12`、`official_before_event` subgroup、pre-trend 診断を中心に示し、その他の仕様は付録的に扱う。
